Project kickoff notes

We agreed on three priorities for the first sprint: search speed, index
accuracy, and a clean interface. Search speed matters most because the
whole point of a local tool is that it should feel instant.

The hash table gives us constant time lookups for exact matches. The trie
handles prefix search and autocomplete. Together they cover most of what
a user will actually type.

Open questions:
- Should fuzzy search be on by default, or opt in?
- Do we need to support folders with subfolders?
- How many files can we index before performance becomes noticeable?

Next steps: benchmark indexing time against a folder of a few thousand
files and see where the bottleneck actually is before optimizing anything.
